# 상세페이지 기획 + 와이어프레임 (올인원)

제품 정보를 한 번 입력하면 기획을 짜고, 섹션 수를 골라 확정하면 같은 대화에서 와이어프레임 캔버스까지 만든다.

## 진행 원칙

1. **사용자 상호작용은 최대 3번**: ① 제품 정보 입력 ② 방향 확인 + 섹션 수 선택 ③ 구성표 확정(와디즈 스타일 사전 점검 결과 포함). 그 뒤 캔버스를 만들고, 수정은 사용자가 말할 때만 한다.
2. **선택형은 버튼**(`ask_user_input_v0`, 한 번에 최대 3문항), 자유 입력은 일반 대화로 받는다. 버튼 도구가 없으면 번호 보기로 묻는다.
3. **쉬운 말만 쓴다.** 책 용어(스토리브랜드, 악당, 문제 3층, 가이드, 빅 도미노, 에피파니 브릿지, 오퍼 스택, 가치사다리)를 사용자에게 묻거나 보여주지 않는다. 대응하는 쉬운 말은 `references/planning-logic.md`.
4. **스스로 정한다.** 고객이 원하는 것, 불편의 진짜 이유, 그때 드는 마음, 핵심 설득 포인트, 공감 한 줄, 구매 3단계, 달라지는 모습, 달라지는 이야기, 구성과 가격 구조, 구매 유도 띠 배너 문구(보통 "지금 구매하기")는 입력된 정보로 유추해서 작성한다. 사용자가 준 문장은 그대로 쓴다.
5. **글자 자리는 하나도 비우지 않고 문장으로 채운다.** 캔버스에 `[설명 입력]`, `[검사 항목 1]`, `[… 입력]`, `[근거 확인]` 같은 대괄호 자리표시를 쓰지 않는다. 설명·소제목·본문·캡션·카드 문구·안내 문구·FAQ 답변은 모두 제품 정보로 직접 써서 채운다. 생성기가 빈칸과 자리표시를 검사하고, 걸리면 채운 뒤 다시 생성한다.
   - 입력된 문구는 그대로 쓰고, 나머지는 입력 정보로 유추해 짧게 쓴다. 과장·단정 표현은 쓰지 않는다.
   - **입력되지 않은 사실도 빈칸으로 두지 않고 샘플 값으로 채운다.** 수치, 순위, 인증·시험 결과, 후기, 가격, 보증 기간, 배송 일정, 교환·환불 조건, 원산지 상세 등은 사용자가 와이어프레임을 SVG로 가져가 실제 근거로 교체하는 초안이다. 후기가 구성에 있으면 샘플 후기로 채운다.
   - **샘플의 선**: 입력된 값이 있으면 항상 그 값을 쓴다. 샘플은 그럴듯하되 과하지 않게 쓰고, 실존하는 기관·인증·특허 번호·시험기관 이름, 실존 인물·실명 후기 작성자, 타사 브랜드는 쓰지 않는다(입력된 것만 예외).
   - **샘플로 채운 항목은 모두 기록한다**: 스펙의 `sample` 목록에 "무엇을 샘플로 채웠는지" 적어 보드 주석 스티커의 `샘플 값 교체`에 남기고, STEP 3 점검 요약과 완료 안내에서 샘플이 들어간 섹션과 항목을 알려 준다. 캔버스 글자에는 표시하지 않는다.
   - 안내 문구(배송·교환·환불·보관·주의)는 안내 문장으로 쓴다. 입력된 조건이 없으면 샘플 조건(출고·교환 가능 기간 등)으로 채우고 `sample` 목록에 남긴다.
   - **확인이 필요한 것은 캔버스 글자에 표시하지 않는다.** 스펙의 `check` 목록에 적어 보드 주석 스티커의 `확인 필요`에 남기고 STEP 3 점검 요약에서도 알린다. (예: "안내 문구는 제가 쓴 일반 문장이라 실제와 맞는지 확인")
6. **제품 종류는 묻지 않고 입력 정보로 판단한다.** 식품·화장품·건강 관련이면 효능·인증 문구를 더 보수적으로 쓰고 확인 필요 목록에 올린다.
7. **섹션 순서와 레이아웃은 제품마다 다르게 정한다.** 장수별 기본 뼈대를 그대로 쓰지 않고, 제품의 구매 결정 요인과 강점 순위를 분석해 강조할 부분을 앞으로 올린다. **레이아웃은 고정된 틀이 아니며 생성할 때마다 무작위로 달라져야 한다.** 목록형 섹션(Point, Option, How-to, Trust, Why 등)은 내용(항목)을 한 번만 쓰고 `entries` 모듈에 맡겨 레이아웃 패턴을 무작위로 정한다. 같은 제품을 다시 만들어도 패턴이 달라진다(후보 패턴, 선택 규칙, 시드는 `references/planning-logic.md`의 "레이아웃 패턴 선택"). 인접한 섹션은 서로 다른 패턴을 쓴다. **나열하는 항목은 입력된 개수에 맞춰 레이아웃이 바뀌어야 한다**(2개는 큰 사진 2열, 4개는 2×2, 5개는 대표 1개 + 2×2, 6개는 3×2 등). 개수를 3~4개로 고정하지 않는다.
8. 진행 상황은 `STEP 2/4`처럼 알려준다. 말투는 친절하고 짧게.

## STEP 1. 제품 정보 입력 (텍스트, 1회)

아래 양식을 보여주고 한 번에 채워 달라고 한다. 모르는 칸은 비워도 되고 "알아서"라고 쓰면 유추한다고 안내한다.

```
1. 제품·브랜드명 (한글/영문, 슬로건):
2. 한 줄 설명:
3. 스펙·가격 (용량, 사이즈, 옵션, 가격):
4. 꼭 알리고 싶은 특징 3~5개:
5. 누가 사나요? (어떤 사람, 어떤 고민):
6. 분위기 (예: 미니멀, 따뜻한, 고급스러운):
7. 믿을 만한 근거 (판매 순위, 수치, 인증, 특허 등 / 기준 시점과 출처도):
```

링크나 기존 상세 설명을 주면 거기서 칸을 먼저 채우고 빈 칸만 묻는다.

## STEP 2. 자동 기획 + 확인 (버튼 1회, 2문항 묶음)

1. `references/planning-logic.md`대로 내부 기획을 만든다.
2. 사용자에게는 아래 5줄만 쉬운 말로 요약해 보여준다.
   - 고객이 이 제품으로 가장 바라는 것
   - 구매를 망설이게 하는 진짜 이유
   - 이것만 믿으면 사고 싶어지는 한 가지
   - 고객 마음을 알아주는 한 줄
   - **페이지에서 가장 먼저 내세울 강점**(분석한 구매 결정 유형과 함께, 예: "시험·인증 근거가 가장 강해서 앞쪽에 배치")
3. 한 번의 버튼 호출에 두 문항을 묻는다.
   - 방향 확인: **이대로 갈게요 / 수정할래요**
   - 섹션 개수: **8장 / 10장 / 12장 / 15장** (와디즈 언급이 있으면 Maker 섹션이 필수라고 한 줄 안내)
4. "수정할래요"면 고칠 부분을 말로 받아 반영하고, 다시 묻지 않고 STEP 3으로 간다.

## STEP 3. 구성표 + 와디즈 스타일 사전 점검 (와이어프레임 만들기 전, 버튼 1회)

와디즈 스타일 점검은 **캔버스를 만들기 전에 항상 실행**한다. 구성표 단계에서 구조와 문구를 먼저 점검하고, 보완을 구성표에 반영한 뒤 만든다.

1. **구성표 초안**: `references/planning-logic.md` 마지막 절(제품 분석, 강점 순위, 유형별 순서, 레이아웃 패턴 선택)로 섹션 순서와 섹션별 레이아웃을 정하고, `references/page-types.md`의 기본 뼈대에서 선택한 장수만큼 고른다.
2. **사전 점검**: 최신 와디즈 안내를 검색해 1회 확인하고(`references/wadiz.md` 사용), 구성표와 카피를 점검한다. 확인하지 못한 것은 못 했다고 밝힌다.
   - **구조 보완**: Maker(메이커 소개), Notice(배송·교환·환불·AS) 등 필수 항목이 빠졌으면 구성표에 **미리 추가**하고 "와디즈 점검으로 추가"로 표시한다. 장수가 늘어난다고 알린다. 제품과 무관한 섹션을 억지로 넣지 않는다.
   - **문구·근거 보완**: 사용자의 문구는 바꾸지 않고 "확인 필요" 목록으로 정리한다. 캔버스 글자에는 표시를 남기지 않는다.
3. **한 번에 보여준다**: 표 `P번호 / 유형 / 구분 / 핵심 카피 / 레이아웃(목록형 섹션은 "무작위"라고 적고 후보 패턴을 알린다) / 들어갈 모듈(이미지 자리마다 어떤 이미지를 넣을지 한 줄 포함) / 배치 이유 / 확인 필요` + 점검 요약(추가된 섹션, 확인 필요 항목, 샘플 값이 들어간 곳, 확인하지 못한 것). **카피는 이미 써서 보여준다.**
4. 버튼: **이대로 와이어프레임 만들기 / 섹션 추가·삭제 / 카피 수정**. 점검으로 추가된 섹션은 "섹션 추가·삭제"로 뺄 수 있다.

## STEP 4. 와이어프레임 캔버스 생성

`references/detailpage-anatomy.md`(참고 상세페이지 분석)와 `references/wireframe-canvas.md`를 먼저 읽고, 모듈은 `references/modules.md`에서 고른다. 핵심만 요약한다.

- **상세페이지처럼 보이게**: 섹션을 **간격 없이 이어 붙여** 한 장의 긴 페이지로 만든다. 배경은 회색 톤(흰/연회색/중간/진한)을 교대하고, 비주얼 섹션은 전체 이미지 배경이다.
- **레이아웃은 섹션마다, 생성할 때마다 다르게**: 목록형 섹션은 `entries` 모듈로 쓰고 생성기가 패턴을 무작위로 고른다(항목 개수에 맞는 패턴만, 앞 섹션과 같은 패턴 금지, 아직 안 쓴 패턴 우선). 고정이 필요한 섹션(비주얼 섹션, Info의 표와 Q&A, 제품 도해 등)만 `pattern`이나 직접 모듈로 지정한다.
- **섹션 틀**: 라벨(POINT 01 등) → 제목(키워드 강조 박스, 가운데 정렬) → 본문 → 비주얼·레이아웃 모듈 → 각주. 한 섹션에 모듈 2~4개, 화면의 절반 이상은 이미지 자리.
- **비주얼 섹션 구성**: 연출 이미지 전체 배경 위에 **상단 카피(로고 → 서브 → 메인 카피 → 서브)**, 중간은 비움, **하단에 픽토그램 바(선택)**. 픽토그램 칸 수는 주요 특징 개수와 같고(6개면 6칸), 키워드로 줄이기 어려우면 바를 생략한다.
- **웹 UI 금지**: 버튼·입력창·격자 표 대신 이미지형 모듈과 띠 배너.
- **편집 가능한 캔버스**: Artifact 도구에 Design(캔버스) 유형이 있으면 섹션 1개 = 아트보드 1개이고, **`scripts/build_canvas.py`로 생성**해서 항상 같은 규칙으로 나오게 한다. 없으면 Figma, 그것도 없으면 `scripts/build_wireframe.py`(글자를 클릭해 수정되는 HTML).
- 구성표의 카피와 모듈을 `spec.json`(`references/wireframe-canvas.md` 6번 형식)로 옮겨 생성기에 넣는다. 예시는 `assets/example-spec*.json`. 생성기가 "내용이 짧아 하단이 비어 보이는 섹션"을 경고하면 전체 폭 이미지·zigzag 항목·모듈을 더해 채운다.
- **가로 860px 고정, 세로는 항상 더 길게(최소 1200px)**, **좌우 여백 40px**, **글자 82px ~ 22px**, **이미지 자리는 글자 없는 검은색 박스**(이미지 설명·비율·`[IMG]` 표기를 캔버스에 넣지 않는다. 어떤 이미지가 들어갈지는 구성표에서 알려준다).
- **모든 글자 자리를 문장으로 채운다.** 대괄호 자리표시와 빈 글자 자리가 없어야 하고(생성기 검사), 입력되지 않은 사실은 샘플 값으로 채운 뒤 `sample` 목록에 남긴다.
- **신뢰 근거**: 순위·특허 같은 메시지 문구는 크게, 실제 수치·출처는 22px로 작게.

완료 후 전할 것: 섹션 수, 이번에 정해진 레이아웃 시드와 섹션별 패턴 목록(생성기 출력), 확인 필요 항목(주석 스티커에 있는 목록)과 샘플 값 교체 목록, "글자를 클릭해 바로 수정할 수 있다"는 안내만 짧게. 점검 결과는 STEP 3에서 이미 보여줬으므로 다시 표로 보여주지 않는다. 수정은 사용자가 말할 때만 한다(섹션 추가·삭제 시 `references/wireframe-canvas.md` 2-1, 6번의 `file` 고정 규칙 사용).

- [ ] 제품 분석으로 섹션 순서를 재배치했고(강점 1위가 앞쪽), 섹션마다 내용에 맞는 모듈을 골랐다 (기본 뼈대 그대로가 아니다)
- [ ] 와디즈 사전 점검을 캔버스를 만들기 전에 했고, 보완을 구성표에 반영했다
- [ ] 특징·구성 나열 섹션의 레이아웃이 입력된 항목 개수에 맞게 달랐다(개수를 임의로 맞추지 않았다)
- [ ] 비주얼 섹션이 상단 카피 + 중간 비움 + (선택) 하단 픽토그램 바 구성이고, 칸 수가 주요 특징 개수와 같다
- [ ] 이미지 자리가 글자 없는 검은 박스이고, 이미지 설명은 구성표에만 있다
- [ ] 목록형 섹션을 `entries`로 써서 레이아웃이 무작위로 정해졌고, 시드와 패턴 목록을 알렸다
- [ ] 섹션마다 레이아웃 패턴이 달랐고, 인접 섹션이 같은 패턴이 아니며, 한 페이지에 패턴이 4종 이상 쓰였다
- [ ] 사용자에게 책 용어를 쓰지 않았다
- [ ] 질문은 3번 이내였다
- [ ] 캔버스에 대괄호 자리표시와 빈 글자 자리가 없다(생성기 검사 통과)
- [ ] 입력되지 않은 사실은 샘플 값으로 채웠고, 모두 `sample` 목록과 안내에 남겼다(실존 기관·인증 번호·실명 후기 없음)
- [ ] 아트보드가 가로 860, 세로 1200 이상, 여백 40, 글자 22~82px이다
- [ ] 섹션이 간격 없이 이어지고, 배경이 회색 톤으로 교대하며, 섹션마다 모듈이 2~4개이고 이미지가 절반 이상이다
- [ ] 웹 버튼·격자 표 없이 이미지형 모듈과 띠 배너로 만들었다
- [ ] 제목 가운데 정렬, 이미지는 검은 박스, 비주얼 섹션 배경은 전체 이미지다
- [ ] 신뢰 근거는 메시지는 크게, 수치·출처는 22px이다
- [ ] 같은 문장이 두 섹션에 중복되면 알렸다
- [ ] 시나리오·연출 이미지가 실제 후기처럼 보이지 않는다
