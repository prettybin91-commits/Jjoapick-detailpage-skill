# 상세페이지 기획 + 와이어프레임 (올인원)

제품 정보를 한 번 입력하면 기획을 짜고, 섹션 수를 골라 확정하면 같은 대화에서 와이어프레임 캔버스까지 만든다.

## 진행 원칙

1. **사용자 상호작용은 최대 4번**: ① 제품 정보 입력 ② 방향 확인 + 섹션 수 선택 ③ 구성표 확정 ④ 완성 후 마무리 버튼. 그 외에는 묻지 않는다.
2. **선택형은 버튼**(`ask_user_input_v0`, 한 번에 최대 3문항), 자유 입력은 일반 대화로 받는다. 버튼 도구가 없으면 번호 보기로 묻는다.
3. **쉬운 말만 쓴다.** 책 용어(스토리브랜드, 악당, 문제 3층, 가이드, 빅 도미노, 에피파니 브릿지, 오퍼 스택, 가치사다리)를 사용자에게 묻거나 보여주지 않는다. 대응하는 쉬운 말은 `references/planning-logic.md`.
4. **스스로 정한다.** 고객이 원하는 것, 불편의 진짜 이유, 그때 드는 마음, 핵심 설득 포인트, 공감 한 줄, 구매 3단계, 달라지는 모습, 달라지는 이야기, 구성과 가격 구조, 버튼 문구(보통 "구매하기")는 입력된 정보로 유추해서 작성한다. 사용자가 준 문장은 그대로 쓴다.
5. **카피는 직접 쓴다. 사실은 지어내지 않는다.**
   - 카피(메인·서브·본문 문구, 시나리오)는 비워 두지 말고 채운다.
   - 사실 정보(수치, 순위, 인증, 특허, 가격, 보증·AS, 일정, 구성품, 후기, 한정·마감)는 사용자가 준 것만 쓴다. 없으면 `[실제 … 입력]`, 근거가 필요하면 `[근거 확인]`을 붙인다.
   - 근거 없는 타사 비교·부정 표현, 단정 표현("완벽", "역대 최대")은 `[근거 확인]`을 붙이거나 빼고 이유를 알려준다.
6. **제품 종류는 묻지 않고 입력 정보로 판단한다.** 식품·화장품·건강 관련이면 효능·인증 문구에 `[근거 확인]`을 더 엄격하게 붙인다.
7. 진행 상황은 `STEP 2/5`처럼 알려준다. 말투는 친절하고 짧게.

## STEP 1. 제품 정보 입력 (텍스트, 1회)

아래 양식을 보여주고 한 번에 채워 달라고 한다. 모르는 칸은 비워도 되고 "알아서"라고 쓰면 유추한다고 안내한다.

```
1. 제품·브랜드명 (한글/영문, 슬로건):
2. 한 줄 설명:
3. 스펙·가격 (용량, 사이즈, 옵션, 가격):
4. 꼭 알리고 싶은 특징 3~5개:
5. 누가 사나요? (어떤 사람, 어떤 고민):
6. 분위기 (예: 미니멀, 따뜻한, 고급스러운):
7. 믿을 만한 근거 (판매 순위, 수치, 인증, 특허 등 / 기준 시점과 출처도):
```

링크나 기존 상세 설명을 주면 거기서 칸을 먼저 채우고 빈 칸만 묻는다.

## STEP 2. 자동 기획 + 확인 (버튼 1회, 2문항 묶음)

1. `references/planning-logic.md`대로 내부 기획을 만든다.
2. 사용자에게는 아래 4줄만 쉬운 말로 요약해 보여준다.
   - 고객이 이 제품으로 가장 바라는 것
   - 구매를 망설이게 하는 진짜 이유
   - 이것만 믿으면 사고 싶어지는 한 가지
   - 고객 마음을 알아주는 한 줄
3. 한 번의 버튼 호출에 두 문항을 묻는다.
   - 방향 확인: **이대로 갈게요 / 수정할래요**
   - 섹션 개수: **8장 / 10장 / 12장 / 15장** (와디즈 언급이 있으면 Maker 섹션이 필수라고 한 줄 안내)
4. "수정할래요"면 고칠 부분을 말로 받아 반영하고, 다시 묻지 않고 STEP 3으로 간다.

## STEP 3. 구성표 확정 (버튼 1회)

1. `references/page-types.md`에서 선택한 장수의 구성안으로 표를 만든다: `P번호 / 유형 / 구분(비주얼·정보) / 핵심 카피 / 들어갈 모듈 / 입력 필요`. **카피는 이미 써서 보여준다.**
2. 버튼: **이대로 와이어프레임 만들기 / 섹션 추가·삭제 / 카피 수정**
3. 추가·삭제를 고르면 원하는 섹션을 말로 받아 구성표를 고쳐 다시 보여주고, 이어서 만든다.

## STEP 4. 와이어프레임 캔버스 생성

`references/detailpage-anatomy.md`(참고 상세페이지 분석)와 `references/wireframe-canvas.md`를 먼저 읽고, 모듈은 `references/modules.md`에서 골라 만든다. 핵심만 요약한다.

- **상세페이지처럼 보이게**: 섹션을 **간격 없이 이어 붙여** 한 장의 긴 페이지로 만든다. 배경은 회색 톤(흰/연회색/중간/진한)을 교대하고, 비주얼 섹션은 전체 이미지 배경이다.
- **섹션 틀**: 라벨(POINT 01 등) → 제목(키워드 강조 박스) → 서브·본문 1~2줄 → 비주얼 모듈 → 각주. 한 섹션에 모듈 2~4개, 화면의 절반 이상은 이미지 자리.
- **웹 UI 금지**: 버튼·입력창·격자 표 대신 말풍선, 원형 배지, 아이콘 알약, 사진 그리드, 막대 차트 같은 이미지형 모듈. 구매 유도는 가로 띠 배너.
- **편집 가능한 캔버스**: Artifact 도구에 Design(캔버스) 유형이 있으면 섹션 1개 = 아트보드 1개이고, **`scripts/build_canvas.py`로 생성**해서 항상 같은 규칙으로 나오게 한다. 없으면 Figma, 그것도 없으면 `scripts/build_wireframe.py`(글자를 클릭해 수정되는 HTML).
- 구성표의 카피와 모듈을 `spec.json`(`references/wireframe-canvas.md` 6번 형식)로 옮겨 생성기에 넣는다. 예시는 `assets/example-spec.json`.
- **가로 860px 고정, 세로는 항상 더 길게(최소 1200px)**, **좌우 여백 40px**, 단일 세로 컬럼.
- **글자 크기는 82px ~ 22px**: 비주얼 제목 82, 정보 제목 64(긴 제목 48), 서브 32, 본문 26, 가장 작은 글씨(수치·출처·각주) 22.
- **섹션 제목은 가운데 정렬**, **이미지 자리는 검은색 박스** + 흰 글씨 라벨.
- **카피는 채워서 만든다.** 비어 있는 것은 사실 정보 자리표시뿐이다.
- **신뢰 근거**: 순위·특허 같은 메시지 문구는 크게, 실제 수치·출처는 22px로 작게.

완료 후 전할 것: 섹션 수, 입력 필요 항목 목록, "글자를 클릭해 바로 수정할 수 있다"는 안내만 짧게.

## STEP 5. 마무리 (버튼 1회)

버튼: **와디즈 스타일 점검 / 수정 요청 / 여기서 끝내기**
- 사용자가 처음부터 와디즈를 언급했다면 점검을 자동 제안한다.
- 점검은 `references/wadiz.md`로 하고, 점검 전에 최신 와디즈 안내를 한 번 검색한다. 확인하지 못한 것은 못 했다고 밝힌다.
- 점검 표는 `항목 / 상태 / 보완 제안`. 보완은 사용자가 승인한 것만 캔버스에 반영한다. 섹션을 끼워 넣을 때는 스펙의 `file`로 기존 파일명을 고정해 생성기로 다시 만든다(`references/wireframe-canvas.md` 2-1, 6번). 수정 전에 현재 `canvas.json`과 고칠 파일을 읽어 사용자의 수동 편집을 덮어쓰지 않는지 확인한다.

## 마무리 체크

- [ ] 사용자에게 책 용어를 쓰지 않았다
- [ ] 질문은 4번 이내였다
- [ ] 카피는 채웠고, 사실 정보는 입력받은 것만 썼다
- [ ] 아트보드가 가로 860, 세로 1200 이상, 여백 40, 글자 22~82px이다
- [ ] 섹션이 간격 없이 이어지고, 배경이 회색 톤으로 교대하며, 섹션마다 모듈이 2~4개이고 이미지가 절반 이상이다
- [ ] 웹 버튼·격자 표 없이 이미지형 모듈과 띠 배너로 만들었다
- [ ] 제목 가운데 정렬, 이미지는 검은 박스, 비주얼 섹션 배경은 전체 이미지다
- [ ] 신뢰 근거는 메시지는 크게, 수치·출처는 22px이다
- [ ] 같은 문장이 두 섹션에 중복되면 알렸다
- [ ] 시나리오·연출 이미지가 실제 후기처럼 보이지 않는다
