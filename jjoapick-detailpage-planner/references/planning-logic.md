# 내부 기획 로직과 쉬운 말 대응표

사용자 입력(제품 정보 7칸)에서 아래 항목을 **스스로 유추**한다. 사용자에게는 오른쪽 "쉬운 말"만 보여준다. 이론 이름은 보여주지 않는다.

## 쉬운 말 대응표

| 내부 개념 | 사용자에게 보이는 말 |
|---|---|
| 고객(주인공)이 원하는 것 | 고객이 이 제품으로 가장 바라는 것 |
| 악당(문제의 원인) | 구매를 망설이게 하는 진짜 이유 |
| 문제 3층(외적·내적·철학적) | 불편한 점 / 그때 드는 마음 / 이래선 안 된다고 느끼는 점 |
| 가이드(공감 + 권위) | 고객 마음을 알아주는 한 줄 + 믿을 만한 근거 |
| 플랜 3단계 | 구매부터 사용까지 3단계 |
| 행동 유도(직접·간접) | 구매 버튼 / 부담을 낮추는 보조 버튼 |
| 실패 vs 성공 | 달라지는 모습(이전 → 이후), 한 덩어리로 |
| 빅 도미노 | 이것만 믿으면 사고 싶어지는 한 가지 |
| 에피파니 브릿지 | 달라지는 이야기 |
| 오퍼 스택 | 구성과 가격 |

## 유추 규칙

1. **고객이 바라는 것**: 타겟의 고민을 한 문장으로 뒤집는다. 사용자가 준 타겟 문장이 있으면 그 말을 살린다.
2. **구매를 망설이게 하는 이유**: 사람이 아니라 상황·선입견으로 쓴다. (예: "작고 냄새난다는 선입견")
3. **불편한 점 / 그때 드는 마음 / 이래선 안 된다**: 세 줄을 각각 다른 층으로 쓴다. 마음은 **감정이나 불안**으로, 이래선 안 된다는 **가치 판단**으로 쓴다. 사용자가 준 문장은 그대로 쓴다.
4. **이것만 믿으면 사고 싶어지는 한 가지**: 망설이는 이유를 뒤집은 한 문장. 우리 집에서도 부담 없이 쓸 수 있다는 식으로 고객 입장에서.
5. **공감 한 줄**: 고객이 속으로 하는 말을 그대로 쓴다. ("~~부터 걱정되시죠") 개인 경험을 지어내지 않는다.
6. **믿을 만한 근거**: 사용자가 준 것만. 메시지(순위, 특허, 판매 규모)는 크게 쓸 문장으로, 실제 수치와 출처는 작은 글씨용 문장으로 나눈다.
7. **사용 3단계**: 제품 정보에서 나온다(먹는 법·쓰는 법·활용 컷). How-to 섹션의 steps 3개가 된다. 구매 안내(보조금·체험·상담)는 Info 섹션 안내 행으로 넣는다.
8. **구매 유도 문구**: 상세페이지에는 웹 버튼이 없으므로 가로 띠 배너 문구로 쓴다. 기본은 "지금 구매하기 ▸"(서비스는 "상담 신청하기 ▸"). 구매 부담을 줄이는 안내(보조금, 샘플 등)가 입력 정보에 있으면 Info 섹션 안내 행에 쓴다.
9. **달라지는 모습**: "이전 → 이후" 한 덩어리. 안 하면 잃는 것과 달라지는 모습을 따로 쓰지 않는다. 12장 이상은 Brand 섹션, 그보다 적으면 Pain 마지막 문장과 Cause의 새로운 생각에 쓴다.
10. **달라지는 이야기(시나리오)**: 별도 섹션을 만들지 않고 Pain 말풍선·상황 캡션, Cause, Brand 문구에 나눠 녹인다. 입력 정보와 위 항목만 이어 붙이고, 실제 후기나 실존 인물처럼 쓰지 않는다.
11. **구성과 가격**: Info 섹션의 제품 상세 정보 표 행으로 넣는다. 입력된 값만 행으로 만들고, 가격·구성품·보증처럼 입력되지 않은 것은 행을 만들지 않는다. 보장·한정·마감도 입력이 없으면 쓰지 않는다.

## 카피 규칙

- 메인 2줄 이내, 서브 1줄, 본문 3줄 이내. "~합니다" 같은 서술형을 피하고 단어 중심으로 짧게.
- 한 섹션에 메시지 하나. 고객이 쓰는 말투.
- 폭 780px 기준 한 줄 글자 수: 82px 약 9자 / 64px 약 12자 / 48px 약 16자 / 32px 약 24자 / 26px 약 30자 / 22px 약 35자. 넘치면 줄바꿈을 넣거나 한 단계 작은 크기로 쓴다.
- 단정 표현("완벽", "최고", "역대 최대")과 효능 표현은 근거가 있을 때만. 없으면 쓰지 않거나 완화하고 확인 필요 목록에 올린다.


## 제품에 맞게 순서·강조·레이아웃 정하기 (STEP 2 내부 분석, 필수)

**장수별 구성안(`page-types.md`)은 중립 기본값이다. 그대로 쓰지 말고, 아래 분석으로 순서와 모듈을 반드시 재배치한다.** 서로 다른 두 제품이 같은 순서·같은 모듈로 나오면 분석을 다시 한다.

### 1. 구매 결정 유형 판정 (주 1개 + 부 0~1개)

| 유형 | 입력에 많이 나오는 신호 | 구매자가 가장 먼저 알고 싶은 것 |
|---|---|---|
| 검증·안전형 | 시험, 인증, 성분, 임상, 특허, 자극 | 믿어도 되는가 |
| 성능·기능형 | 스펙, 센서, 용량, 모드, 기술 | 얼마나 잘 되는가 |
| 감성·디자인형 | 소재, 컬러, 무드, 질감, 스타일 | 내 취향·공간에 어울리는가 |
| 가격·혜택형 | 구성, 할인, 혜택, 세트, 보조금 | 얼마나 이득인가 |
| 서비스·전문가형 | 강의, 커리큘럼, 경력, 수강, 상담 | 누가 무엇을 얻게 해 주는가 |

### 2. 강점 순위 매기기
입력한 특징·근거를 아래 기준으로 평가해 1~5위로 정한다. **사용자가 적은 순서는 중요도가 아니다.**
1. 구매 장벽을 가장 크게 낮추는가
2. 경쟁 제품과 가장 다른가
3. 증거(시험·인증·수치·순위)가 가장 강한가

- **1위 강점**은 Hero 제목, 바로 다음 섹션, 첫 번째 Point, Proof의 큰 메시지에 반복해서 올린다.
- Point는 **강점 순위 순서대로** 한 섹션에 강점 하나씩 배정한다.
- 증거가 없는 강점은 순위를 낮추고 확인 필요 목록에 올린다.

### 3. 유형별 섹션 순서 (Hero는 항상 첫째, Info·Notice는 항상 마지막)

| 유형 | 중간 순서 | 앞으로 올릴 것 | 줄이거나 뒤로 보낼 것 |
|---|---|---|---|
| 검증·안전형 | Trust → Proof → Pain → Cause → Point(성분·기술) → How-to → Review | 시험 수치·인증(Trust, Proof) | Cause, Why |
| 성능·기능형 | Trust(핵심 스펙) → Point(기능별) → Pain/Cause(선입견 있을 때만, 짧게) → Proof → How-to | 기능·스펙 Point | Pain, Review |
| 감성·디자인형 | Brand(무드) → Point(소재·디테일, 큰 사진) → Option(컬러·사이즈) → How-to(스타일링) → Review | Brand, Point, Option | Pain, Cause, Proof(수치) |
| 가격·혜택형 | Offer(구성·혜택·가격) → Why → Proof → Point → How-to | Offer, Why | Pain, Cause |
| 서비스·전문가형 | Pain → Cause → Maker(경력·자격) → Proof(수강생 결과) → How-to(커리큘럼) → Review → Offer | Maker, Proof | Option |

부 유형이 있으면 주 유형 순서를 바탕으로 부 유형의 앞으로 올릴 섹션 1~2개를 앞쪽에 끼운다.

### 4. 장수에 맞추기
- 사용자가 고른 장수(8/10/12/15)에 맞춰 **덜 중요한 섹션부터 뒤에서 덜어낸다.** 앞으로 올릴 섹션은 마지막까지 남긴다.
- 장수를 늘릴 때는 Point를 강점 순위대로 추가하고, Review·Why·Brand·Notice를 더한다.

### 5. 섹션 안의 레이아웃: 내용 유형에 맞는 모듈
같은 Point라도 담는 내용이 다르면 모듈이 달라야 한다.

| 내용 유형 | 쓰는 모듈 |
|---|---|
| 시험 수치·성능 비교 | chart, percent_bars (수치는 22px) |
| 구조·원리·부위 설명 | callout(제품 도해) |
| 사용 순서·절차·커리큘럼 | steps |
| 이전 → 이후, 선입견 → 새 관점 | vs |
| 컬러·옵션·구성·맛 | photo_grid(2열, 캡션) |
| 분위기·무드·사용 장면 | 전체 이미지 비주얼 섹션 + photo_grid(3열) |
| 특징 5개 이상 나열 | check_grid, icon_cards |
| 인증·특허·수상 | claim(메시지 크게) + cert_grid |
| 고객 고민 | bubbles |
| 동작·변화 | image(GIF 자리) |
| 질문이 많은 제품 | qa |

- 1위 강점은 일반 정보 섹션보다 **더 눈에 띄게**(전체 이미지 배경의 `photo` 섹션, 대형 claim) 만든다.
- 감성·디자인형은 이미지 비중을 70% 이상으로, 텍스트는 짧게.
- 검증·안전형은 수치와 인증 메시지를 크게, 수치·출처는 22px로 작게.

### 6. 구성표에 배치 이유를 적는다
각 섹션 옆에 한 줄로 이유를 쓴다. (예: "시험 수치가 가장 강한 근거라 2번째에 배치", "비교할 경쟁 제품이 없어 Cause는 생략")


## 레이아웃 패턴 선택 (STEP 3 구성표에서 섹션마다 정한다)

**레이아웃은 고정이 아니다.** 같은 유형(Point 등)이라도 제품 성향과 내용 분량에 맞는 패턴을 골라야 하고, 두 제품이 같은 패턴 배열로 나오면 다시 고른다.

### 1. 패턴 목록

| 패턴 | 쓰는 모듈 | 느낌 |
|---|---|---|
| 중앙 세로 | headline + image/icon_row/steps 쌓기 | 기본, 안정적 |
| 가로 분할 | split | 사진과 설명을 나란히 |
| 좌우 교차 | zigzag | 항목마다 사진, 리듬감 |
| 이미지 위 글자 | overlay (+ 전체 폭 image) | 분위기, 임팩트 |
| 타임라인 | timeline | 과정, 이미지 없이 가볍게 |
| 큰 번호 리스트 | numbered_list, index | 편집물 느낌, 순서 |
| 데이터 행 | stat_rows, chart, percent_bars | 큰 값 + 작은 설명 |
| 원형 사진 | circle_row | 대표 3가지, 부드러움 |
| 사진 그리드 | photo_grid, check_grid | 여러 컷, 옵션 |
| 띠·선언 | ticker, quote, claim | 구분, 한 줄 메시지 |

### 2. 제품 성향별로 많이 쓰는 패턴

| 유형 | 우선 패턴 | 줄이는 패턴 |
|---|---|---|
| 감성·디자인형 | 이미지 위 글자, 좌우 교차, 원형 사진, 사진 그리드(큰 컷), 전체 폭 이미지 | 데이터 행, 중앙 세로 |
| 검증·안전형 | 데이터 행, 띠·선언(claim), 사진 그리드(인증서), 가로 분할(성분·도해), 타임라인(시험 과정) | 이미지 위 글자 |
| 성능·기능형 | 가로 분할(도해+설명), 타임라인, 큰 번호 리스트, 차트, 이미지 위 글자(히어로) | 원형 사진 |
| 가격·혜택형 | 데이터 행(가격·혜택), 띠(ticker), 가로 분할(구성), checklist | 타임라인 |
| 서비스·전문가형 | 가로 분할(인물+소개), 타임라인(커리큘럼), 띠·선언(quote), 데이터 행(성과) | 원형 사진 |

### 3. 선택 규칙
1. **인접한 두 섹션은 서로 다른 패턴**을 쓴다. 같은 패턴 연속 금지.
2. 한 페이지에 **서로 다른 패턴을 4종 이상**(12장 이상은 6종 이상) 쓴다.
3. **Point가 여러 개면 Point마다 다른 패턴**을 쓴다.
4. 내용 분량으로 정한다.
   - 사진 + 설명 2~4줄 → 가로 분할
   - 사진 있는 항목 2~4개 → 좌우 교차
   - 대표 사진 한 장으로 분위기·메시지 → 이미지 위 글자
   - 이미지 없는 단계 3개 안팎 → 타임라인, 순서 안내 → 큰 번호 리스트
   - 가격표·수치·순위 → 데이터 행(큰 값 + 22px 설명)
   - 원료·구성·환경 대표 3가지 → 원형 사진
5. 첫 화면(Hero)과 마무리(Brand 또는 Info)는 서로 다른 패턴으로 한다. 1위 강점 섹션은 이미지 위 글자나 전체 폭 이미지로 크게 보여 준다.
6. 섹션 제목(headline)은 항상 가운데 정렬이다. 패턴은 제목 아래 본문 영역에서 바뀐다.
7. 내용이 짧아 하단이 비면 전체 폭 이미지, 좌우 교차 항목, 추가 모듈로 채운다(생성기 경고 참고).
8. 구성표의 `레이아웃` 열에 패턴 이름을 적는다. (예: "타임라인", "가로 분할")


### 4. 항목 개수에 맞춘 레이아웃 (패턴 선택의 핵심)
같은 "특징 나열" 섹션이라도 **입력된 특징·구성 개수에 따라 레이아웃이 달라져야 한다.** 개수를 4개 안팎으로 억지로 맞추지 않는다.

| 개수 | 레이아웃 |
|---|---|
| 1 | 넓은 대표 카드 또는 이미지 위 글자 |
| 2 | 큰 사진 2열(마주 보는 구성), 또는 좌우 교차 |
| 3 | 3열 사진 카드, 또는 원형 사진(circle_row), 글이 길면 번호 리스트·좌우 교차 |
| 4 | 2×2 카드 |
| 5 | 대표 1개 + 2×2 (1순위 강점을 대표로) |
| 6 | 3×2 소형 카드 |
| 7 | 대표 1개 + 3×2 |
| 8 | 2×4 카드 |
| 9 이상 | 번호 리스트(큰 번호 + 한 줄 설명) |

- 개수가 정해지면 **강점 순위 1위를 대표 카드·첫 칸에** 둔다.
- 글이 길면(항목당 30자 이상) 열 수를 줄이거나 리스트·좌우 교차로 바꾼다.
- 같은 개수의 목록이 한 페이지에 여러 번 나오면(특징 4개와 후기 4개 등) 서로 다른 패턴을 쓴다.
- 구현은 `feature_set` 모듈(자동 선택)을 쓴다.


## 비주얼 섹션의 하단 픽토그램 바 (넣을지, 몇 칸으로 할지)
- **칸 수는 주요 특징 개수와 같다.** 입력된 핵심 특징이 6개면 6칸, 3개면 3칸이다. 6칸까지는 한 줄, 7~8개는 4칸씩 두 줄, 9개 이상이면 상위 8개만 쓴다(강점 순위 순).
- **넣는 경우**: 특징을 "아이콘 + 짧은 키워드(용량·가격·인증·사용법·산지 등)"로 줄일 수 있을 때. 칸마다 작은 문구(항목)와 굵은 값을 쓴다.
- **생략하는 경우**: 특징이 긴 문장 위주라 키워드로 줄이기 어렵거나, 감성·분위기 중심이라 하단을 이미지로 비워 두는 편이 나을 때. 상단 카피만 둔다.
- 비주얼 섹션이 여러 개면 섹션마다 바를 넣을지 따로 판단한다(첫 화면 Hero에는 넣고 중간 Brand에는 생략하는 식).
- 사실 정보(용량·가격·인증)가 값에 들어가면 입력된 것만 쓴다. 입력이 없는 칸은 만들지 않고 입력된 다른 특징으로 채운다.


## 빈칸 없이 채우는 규칙 (대괄호 자리표시 금지)

캔버스의 모든 글자 자리는 문장으로 채운다. `[설명 입력]`, `[검사 항목 1]`, `[… 입력]`처럼 비워 두지 않는다. 생성기가 빈칸과 자리표시를 검사한다.

| 글자 자리 | 채우는 법 |
|---|---|
| 서브·본문·설명·캡션 | 제품 정보와 강점으로 직접 쓴다 (과장·단정 없이 짧게) |
| 카드·단계·타임라인·체크 문구 | 입력된 특징을 풀어 쓴다. 수치는 넣지 않는다 |
| 사진 캡션·원형 사진 설명 | 사진이 보여 줄 내용을 짧게 쓴다 (예: "씹을수록 단단해요") |
| 좌우 교차·분할의 불릿 | 입력된 특징에서 2~3개를 뽑아 쓴다 |
| FAQ | 입력 정보로 답할 수 있는 질문만 만들고 답까지 쓴다 |
| 스펙 표 | 입력된 항목은 그대로, 가격·용량·원산지처럼 표에 필요한 항목은 샘플 값으로 채우고 `sample`에 적는다 |
| 배송·교환·환불·보관·주의 | 안내 문장으로 쓴다. 입력된 조건이 없으면 샘플 조건(예: 출고·교환 가능 기간)으로 채우고 `sample`에 적는다 |
| 수치·순위·인증·시험 결과 | 입력된 것을 쓴다. 없으면 그럴듯한 샘플 값으로 채우고(기준 시점·집계 방식 문장 포함) `sample`에 적는다. 실존 기관·인증 번호·특허 번호는 쓰지 않는다 |
| 후기 | 구성에 Review가 있으면 샘플 후기로 채운다(실명·실존 인물 금지, 호칭은 "구매자" 정도). `sample`에 적는다 |
| 가격·보증·원산지 상세 | 입력된 것만 쓴다. 없으면 샘플 값으로 채우고 `sample`에 적는다 |

- **입력되지 않은 사실은 샘플 값으로 채운다.** 사용자가 SVG로 가져가 실제 근거로 교체하는 초안이기 때문이다. 입력된 값이 있으면 항상 그 값을 쓴다.
- **샘플의 선**: 실존하는 기관·인증·특허 번호·시험기관 이름, 실존 인물·실명 후기 작성자, 타사 브랜드는 쓰지 않는다. 수치는 그럴듯하되 과하지 않게, 순위·"1위" 같은 표현은 입력이 없으면 쓰지 않는다.
- **교체 목록**: 샘플로 채운 항목은 스펙의 `sample`에 "무엇을 어떤 값으로 채웠는지" 적는다. 보드 주석 스티커의 `샘플 값 교체`와 STEP 3 점검 요약, 완료 안내에서 알린다. 캔버스 글자에는 표시하지 않는다.
- **확인 목록**: 제가 쓴 일반 안내 문장은 `check`에 적어 `확인 필요`로 남긴다.


### 5. 무작위 선택 (생성할 때마다 레이아웃이 달라지게)
같은 내용으로 다시 만들어도 레이아웃이 똑같이 나오면 안 된다. 그래서 **목록형 섹션의 레이아웃은 직접 고르지 않고 `entries` 모듈이 무작위로 정한다.**

- **내용은 한 번만 쓴다**: `entries`에 `items[{title, text, label(사진 자리 이름, 선택)}]`와 `kind`(features·steps·prices·options·reasons)를 주면, 생성기가 아래 후보 중에서 고른다.
  카드 격자 / 좌우 교차 / 세로 타임라인 / 큰 번호 리스트 / 원형 사진 / 데이터 행 / 사진 그리드 / 가로 분할 + 목록 / 2열 대비 / 체크 목록 / 이미지 위 글자 + 카드
- **후보 걸러내기**: 항목 개수에 맞는 패턴만(원형 사진은 3개, 2열 대비는 2개 등), `kind`에 맞는 패턴만(단계에는 타임라인·번호 리스트, 가격에는 데이터 행 등). 가격처럼 모양이 중요하면 `allow`로 후보를 줄인다.
- **선택 순서**: 앞 섹션과 같은 패턴 제외 → 아직 안 쓴 패턴 우선 → 그 안에서 무작위.
- **선택 세부도 무작위**: 사진 비율(3:4·1:1), 사진 좌우 위치, 전체 폭 이미지(`lead_image`)를 앞이나 뒤에 두는 것 등.
- **시드**: 생성할 때 시드가 정해지고 출력된다. 같은 시드와 같은 스펙이면 같은 배치로 다시 만들어진다. 마음에 드는 배치는 `--seed 번호`로 다시 뽑고, 일부 섹션만 고정하려면 `entries`의 `pattern`을 지정한다.
- 고정이 필요한 섹션(Hero·Brand 같은 비주얼 섹션, Info의 표와 Q&A, 특수한 도해)은 직접 모듈로 쓴다. 무작위는 목록형 섹션에 적용한다.
